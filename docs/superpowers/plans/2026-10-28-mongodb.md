# MongoDB and the Document Database Family Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add MongoDB as the first engine of a new document family, with the same guarantees as a SQL connection (connect, explore, browse, query, controlled writes, document edits, schema, plans, activity, read-only SQL), on a contract a second document engine can implement with one crate and one line in `drivers.rs`.

**Architecture:** The session thread, job queue, panic isolation, run counter, cancel retries and streaming move out of `core/src/session.rs` into a generic `core/src/worker.rs`, so a second contract can share them. A new `core/src/document/` module holds an engine-neutral value model (`Value`, `Document`, `Ext`), the blocking `DocumentAdapter` trait, the static `Language` and detected `Capabilities` a driver describes itself with, and a `DocumentSession` over the shared worker that owns every rule (read-only refusal, heavy refusal, transactions per script, checked document changes). A new crate `crates/mongo` (`kuery-mongo`) exports `pub static DRIVER: DocumentDriver`: a blocking adapter over the `mongodb` crate on its own tokio runtime, a hand-written mongosh-subset parser that is never evaluated, and a protocol guard independent of that parser. The app gets one `Document` branch per dispatch point and generic document UI: a lazy sidebar tree, a Collection tab and a Console tab.

**Tech Stack:** Rust (workspace toolchain), `mongodb = { version = "3.9", default-features = false, features = ["compat-3-3-0", "bson-3", "rustls-tls", "dns-resolver"] }` (3.9.1 pulls only `ring`, no `aws-lc-rs` and no openssl; roots from webpki-roots), tokio, serde_json (`preserve_order`), base64 0.22 and proptest (both already in `Cargo.lock`), sqlparser 0.63 `GenericDialect` (phase 9), gpui-kit `=0.7.3` with `tree-sitter-javascript`, Docker `mongo:8.0`.

**Spec:** `docs/superpowers/specs/2026-10-28-document-databases-design.md`

## Global Constraints

- Driver id `mongodb`, name `MongoDB`, aliases `mongo`, `atlas`, `documentdb`, `cosmos`, `ferretdb`, `percona`; default port 27017; family `Family::Document`, label `Document`. Compatible products are aliases of this one driver, told apart by detected capabilities, never by separate drivers.
- Owner decisions (the spec's open questions, settled): (1) contract first; no CouchDB/SurrealDB validation engine is built (phase 13 is skipped, and phase 12, the Redis gap, goes on its own branch). (2) The refactor phases 2 and 3 come first even though they delay the first visible MongoDB line. (3) One catalog `DocumentSession` per connection, plus one session per console tab and per collection tab through `reopen`, all sharing one `mongodb::Client` (one pool). (4) No interactive transactional write mode: atomicity only per script and per staged batch of document changes. (5) Connection options are data-driven form fields (`DriverInfo.options`, `ConnectionSpec.options` with `serde(default)`, keys limited to the driver's allowlist), and pasting a `mongodb://` URI splits it into the fields and moves its password to the keychain. (6) gpui-kit's `tree-sitter-javascript` feature is added. (7) On production, an authenticated Mongo user that can write only gets the notice; Kuery still refuses writes itself. (8) Redis stays as it is, apart from the extracted shared write review. (9) SQL over documents stays read-only.
- No `if mongo` branches in shared code: engine differences reach core and the app only through `Language`, `Capabilities` and `DriverInfo`.
- Never drop a `mongodb` future mid-operation: every operation is spawned on the driver's runtime and its `JoinHandle` is awaited; a cancel kills the operation on the server (`killOp` by comment tag) and keeps waiting for a bounded grace.
- No JavaScript evaluation anywhere: the console accepts a parsed subset of mongosh; variables, functions, loops, `forEach`, `load()`, `db.eval`, `mapReduce` and `Mongo()` are refused with "Kuery runs MongoDB commands, not JavaScript: one command per statement".
- Read-only is never claimed as server-enforced unless detected: `Enforcement::Server` only when at least one user is authenticated and none of the privileges reported by `connectionStatus { showPrivileges: true }` is a write action. The text says "at connect time".
- BSON types survive every round trip: `NumberLong` stays Int64, `Decimal128` stays Decimal128, `42.0` is a Double. Edits never turn a removed field into `null`.
- `rustls` with `ring` only: `cargo tree -i aws-lc-rs` shows only the existing tiberius path; `cargo tree -i openssl-sys` finds nothing. Private CAs come from a `tlsCAFile` option.
- Credentials never reach `project.toml`: the password goes to the keychain; option keys outside the driver's allowlist are refused; secrets such as `tlsCertificateKeyFilePassword` are never options.
- Dev server: `mongo:8.0`, single-node replica set `rs0`, auth on (keyfile generated at start), `enableTestCommands=1`, port `27019` (mongod listens on 27019 inside the container too, so the member name `localhost:27019` works from the host), root user `kuery` / `kuery` and read-only user `kuery_ro` / `kuery` with role `read` on `shop` (development only, documented in `dev/compose.yaml` and `.env.example`), database `shop`. ## Review Focus

1. **A write slipping through read-only** (a parser bug, `$out` nested in `$facet` or `$lookup.pipeline` or `$unionWith`, a write inside `explain`, `db.runCommand({insert: …})`, `findOneAndUpdate` mistaken for a read) — refused by the classifier, and if the classifier is fooled, by `wire::guard` on the final BSON command, with the data unchanged. Tests in Tasks 5, 10 and 19.
2. **A server without authentication shown as server-enforced read-only** (the default Docker `mongo`: `connectionStatus` returns empty privilege lists while anyone can write) — must be `ClientOnly` with the notice "this server has no authentication". Tests in Tasks 10 and 11.
3. **Cancel** — a long `find` or the `sleep` test command stops within seconds via `killOp` by comment, the spawned task is awaited (never dropped), the session keeps working, and a cancel that lands after the run ended never reaches the next run. Tests in Tasks 5, 10 and 19.
4. **BSON type fidelity** — `NumberLong`, `NumberDecimal`, `ISODate`, `ObjectId`, `UUID`, `Timestamp`, regexes, `MinKey`/`MaxKey` and `42.0` survive print → parse → BSON → print; an edit of one field leaves every other field's type alone. Tests in Tasks 9 and 24.
5. **Absent versus null** — the grid shows an absent field as a dimmed "—" and an explicit `null` as the usual italic NULL; deleting a field in an edit produces `$unset`, never `null`; the optimistic check uses `$exists: false` for fields that were absent. Tests in Tasks 4, 15 and 24.
6. **Heterogeneous collections** — a field that first appears in a later batch adds a column without resetting the grid, earlier rows show it as absent, and the column count stops at 200. Tests in Tasks 4 and 15.
7. **Credentials and tunnels** — a pasted URI's password lands in the keychain and never in `project.toml`; unknown options are refused by name; through an SSH tunnel `directConnection=true` is forced and `+srv` and host lists are refused with "Through SSH, Kuery reaches a single member". Tests in Tasks 7, 12 and 13.

```rust
                          pub(crate) run: AtomicU64, pub(crate) cancelled: AtomicBool }

/// The adapter, on the session's thread.
pub(crate) struct Worker<A: ?Sized> { pub(crate) adapter: Box<A>, pub(crate) access: Access,
                                      pub(crate) state: Arc<State>, pub(crate) canceller: Canceller }
impl<A: ?Sized> Worker<A> {
    pub(crate) fn writable(&self) -> Result<(), QueryError>;
    pub(crate) fn abandon(&mut self);
    pub(crate) fn begin_run(&mut self);
    pub(crate) fn end_run<T>(&mut self, outcome: Result<T, QueryError>) -> Result<T, QueryError>;
}

/// Events a streamed job sends: how it ends well, and how it fails.
pub(crate) trait Streamed: Send + 'static {
    type Summary: Send + 'static;
    fn finished(summary: Self::Summary) -> Self;
    fn failed(error: QueryError) -> Self;
}

pub(crate) struct Handle<A: ?Sized + Driven> { jobs: mpsc::Sender<Job<A>>, state: Arc<State>, canceller: Canceller }
impl<A: ?Sized + Driven> Clone for Handle<A> { … }
impl<A: ?Sized + Driven> Handle<A> {
    /// Opens the adapter on a thread of its own and hands back the handle with
    /// what `describe` read from the adapter there.
    pub(crate) fn open<I: Send + 'static>(
        access: Access,
        open: impl FnOnce() -> Result<Box<A>, String> + Send + 'static,
        describe: impl FnOnce(&A) -> I + Send + 'static,
    ) -> impl Future<Output = Result<(Handle<A>, I), String>> + Send + 'static;
    pub(crate) fn call<T, F>(&self, job: F) -> impl Future<Output = Result<T, QueryError>> + Send + 'static + use<A, T, F>
    where T: Send + 'static, F: FnOnce(&mut Worker<A>) -> Result<T, QueryError> + Send + 'static;
    pub(crate) fn stream<E: Streamed, F>(&self, job: F) -> async_channel::Receiver<E>
    where F: FnOnce(&mut Worker<A>, &async_channel::Sender<E>) -> Result<E::Summary, QueryError> + Send + 'static;
    /// Stops the running job, now and every quarter second while it goes on (40 × 250 ms).
    pub(crate) fn cancel(&self);
    pub(crate) fn in_transaction(&self) -> bool;
}
```

Every SQL rule stays in `impl Worker<dyn Adapter>` in `session.rs` (`read_with`, `run_script`, `apply`, `preview`, …); `run_script` uses `self.canceller` as before. `impl Streamed for Event { type Summary = Summary; … }`. The public API of `Session` does not change.

Rules `DocumentSession` owns (each pinned by a test):
- `run` analyses the text with `language.analyze` before anything reaches the adapter; a `ParseError` fails as `Rejected(Rejection::Parse("line L, column C: …"))`. With `Access::ReadOnly` or `RunMode::Read`, any statement whose kind is not `Read` fails the whole run as `Rejected(Rejection::Statement(summary))` and nothing runs; `RunMode::Write` on a read-only session is `WritesDisabled`. A `heavy` statement with `Heavy::Refuse` fails as `Rejected(Rejection::Heavy(summary))`. `browse` applies `language.check_filter` the same way.
- Documents stream as `DocEvent::Documents` in batches growing ×4 from `first_batch_rows` to `max_batch_rows`; each statement's `Outcome` follows as `DocEvent::Outcome`; a reader that goes away stops the run and calls the canceller.
- A `Write` run of several statements goes in one transaction (`begin` … `commit`, `abort` on failure or cancel) when `capabilities.transactions` is `Multi`; a `Schema` statement in such a script refuses the whole script before it runs ("{summary} cannot run inside a transaction: run it on its own"); a single statement runs without a transaction. Without transactions the script runs statement by statement and stops at the first failure; the outcomes already sent tell what ran.
- `apply` needs `ReadWrite`; each change must meet `DocChange::expected` (`Update`/`Replace`/`Delete` match exactly 1, `Insert` inserts exactly 1) or fails as `RowMismatch { sql: <the change rendered with language.render>, expected, actual }`. With `Multi`, all changes go in one transaction and a failure keeps none (`applied: 0`); without, it stops at the first failure and `applied` counts what was kept. No transaction is ever left open between calls.
